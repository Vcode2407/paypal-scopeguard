# PayPal sandbox credential setup

Run `npm run paypal:configure` from the repository in a terminal. Both the sandbox client ID and secret are entered without echo. The command saves only local credentials; it does not authenticate with PayPal, dispatch inference, create an invoice or restart ScopeGuard. Keep values out of chat, screenshots, shell arguments, command history and exported evidence.

For an explicitly authorized automated transfer, `npm run paypal:configure -- --stdin` accepts one UTF-8 JSON object containing exactly `clientId` and `secret` through a private stdin pipe (maximum 1,600 bytes). Do not construct a shell command containing these values or save an intermediary plaintext file. Success/error output excludes the entered values and helper diagnostics.

The exact destination is `<repository>/data/paypal-sandbox/credentials.json`; the existing `data/` ignore rule covers it. Windows encrypts the credential envelope with DPAPI **CurrentUser** and a fixed application purpose. Its directory and files have protected DACLs restricted to the current user and SYSTEM. Only that Windows user context can decrypt the DPAPI record. Plaintext exists in application/private helper memory during setup and use. This does not protect against a malicious process already running as the same user. [Microsoft DPAPI scope](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.dataprotectionscope?view=windowsdesktop-9.0).

Linux/macOS have no DPAPI in this implementation: the credential envelope is **plaintext**, protected by current-user ownership, directory mode 0700 and file mode 0600. The inner schema and checksum detect malformed or accidentally corrupted data; the checksum is not authentication against a user who can rewrite that file. Windows also validates the decrypted envelope because cryptographic corruption can require additional application checks. [Microsoft integrity guidance](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptunprotectdata).

Loading rejects unsafe existing ownership/permissions, symbolic links or junctions in the path, Windows reparse points checked by the ACL helper, nonregular or hard-linked credential files, wrong-platform records, malformed/oversized data and decrypt/checksum failures. It does not repair exposed storage on load. Imports use a protected random temporary file, an exclusive importer lock and atomic replacement. An existing lock is not automatically deleted; confirm the importer has stopped before removing a stale lock. A refusal before replacement preserves the old record. A final verification failure can occur after replacement; do not restart the backend until setup succeeds. If existing storage has unsafe permissions, review and correct it locally before importing again.

The existing backend environment option remains supported: a complete valid `PAYPAL_SANDBOX_CLIENT_ID`/`PAYPAL_SANDBOX_SECRET` pair takes precedence without reading the protected store. One missing key, explicitly empty values or malformed values disable PayPal setup; they never fall back to stored credentials. Remove both legacy PayPal variables from `.env` and the backend's process environment to use the protected store. Environment/`.env` values do not receive DPAPI protection from this feature. If neither variable nor a stored record exists, PayPal remains unconfigured. Invalid protected configuration disables this provider while the local review workflow can still start.

The Windows helper uses Windows PowerShell's built-in module directory and a Windows system-only PATH, excluding inherited PowerShell 7/third-party module paths and provider credentials. The built-in module path is enforced again inside PowerShell before module loading, because startup can insert AllUsers directories. Its 10-second deadline remains enforced; refusals terminate the helper, close all private pipes and stop collecting output. Failures can retain only a fixed action, failure category, last completed stage and child-exit boolean; paths, stdin, decrypted output and raw helper errors are excluded. The first publication's Windows CI run failed seven synthetic storage cases at this deadline while Ubuntu passed; those observations do not establish whether startup, module initialization or pipe completion caused the timeouts. [Historical run](https://github.com/Vcode2407/paypal-scopeguard/actions/runs/38214926702).

Restart ScopeGuard only after stopping its existing backend. The default remains `http://127.0.0.1:4185`. Assessments and quotes disappear on restart. Loading credentials makes no PayPal call, and `paypalConfigured:true` confirms only that usable credentials were loaded; it does not prove OAuth or Invoicing permission.

For one authorized fictional sandbox demonstration, explicitly choose **Local rules**, review the FAQ page ($200) and booking integration ($300), approve the USD 500 quote, then use the actual personal sandbox buyer email. Creating a draft performs sandbox OAuth as needed, one invoice POST and a details GET that checks the actual currency/total. Do not create another quote automatically following an uncertain creation result; inspect the sandbox dashboard first. No send/payment operation is implemented. Current Invoicing references specify `https://uri.paypal.com/services/invoicing/invoices/readwrite` for creation and `https://uri.paypal.com/services/invoicing/invoices/read` for retrieval. [Create draft](https://developer.paypal.com/api/invoicing/v2/invoices-create), [Get details](https://developer.paypal.com/api/invoicing/v2/invoices-get).

Credential-storage regression tests use synthetic keys in temporary directories only. They exercise the platform's actual storage protection, corruption refusal, environment precedence, links, permissions and import-lock preservation. Process-level importer tests reject oversized stdin, malformed UTF-8/JSON and unsupported arguments with redacted output. A calibrated fixture guard intercepts storage filesystem calls before path access, verifying those invalid inputs never check, read or write the default credential store. They do not establish any live PayPal or AI integration result; those gates remain pending.
